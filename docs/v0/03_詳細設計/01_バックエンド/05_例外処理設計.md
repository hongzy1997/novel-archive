## 1. 例外処理概要

Backendで発生するAPIエラーは`GlobalExceptionHandler`で共通的に処理する。

ControllerやServiceで個別にHTTPレスポンスを生成せず、発生した例外に応じて`GlobalExceptionHandler`がHTTP Statusおよびレスポンス内容を決定する。

```text
Controller / Service
        ↓
      Exception
        ↓
GlobalExceptionHandler
        ↓
HTTP Response
```

## 2. 独自例外

### 2.1 NovelNotFoundException

指定された小説が存在しない場合に使用する。

主な発生箇所は以下とする。

- 小説詳細取得
- 小説更新
- 小説削除

発生時は`404 Not Found`を返却する。

### 2.2 NovelAlreadyExistsException

同一タイトルの小説が既に存在する場合に使用する。

主な発生箇所は以下とする。

- 小説登録
- 小説更新

発生時は`409 Conflict`を返却する。

## 3. Validationエラー

`NovelRequest`のBean Validationでエラーが発生した場合は、`MethodArgumentNotValidException`を共通処理する。

HTTP Statusは以下とする。

```text
400 Bad Request
```

エラー内容は、フィールド名とメッセージの組み合わせで返却する。

```json
{
  "title": "タイトルは必須です。",
  "rating": "未読の場合は評価できません。未読以外の場合は評価が必須です。"
}
```

複数項目にエラーが存在する場合は、各項目のエラーをまとめて返却する。

## 4. 業務例外

独自例外発生時は`ErrorResponse`を利用してエラー内容を返却する。

### 4.1 小説未存在

```text
404 Not Found
```

```json
{
  "message": "対象の小説が存在しません。id=9999"
}
```

### 4.2 タイトル重複

```text
409 Conflict
```

```json
{
  "message": "同じタイトルの小説が既に登録されています。title=小説タイトル"
}
```

## 5. 例外一覧

| 例外 | HTTP Status | 発生条件 |
|---|---|---|
| MethodArgumentNotValidException | 400 Bad Request | RequestのValidationエラー |
| NovelNotFoundException | 404 Not Found | 指定した小説が存在しない |
| NovelAlreadyExistsException | 409 Conflict | 同一タイトルの小説が存在する |

```text
   ↓

   ↓

   ↓

   ↓
```

```text
   ↓
```


## 7. 責務分離

Serviceではエラー条件を判定し、必要な例外を発生させる。

`GlobalExceptionHandler`では発生した例外をHTTPレスポンスへ変換する。

```text
Service
= エラー条件の判定

GlobalExceptionHandler
= HTTP Status・レスポンスへの変換
```

これにより、ControllerおよびService内にHTTPエラー処理を分散させない構成とする。
