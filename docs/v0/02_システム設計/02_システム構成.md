## 1. 概要

Novel Archiveは、Frontend、Backend、Databaseの3層で構成する。

各環境はDockerコンテナとして実行し、
Docker Composeによって一括管理する。


## 2. システム構成図

```text
Browser
    │
    │ HTTP
    ▼
┌─────────────────────────┐
│ Frontend Container      │
│                         │
│ React                   │
│ nginx                   │
└────────────┬────────────┘
             │
             │ /api/*
             ▼
┌─────────────────────────┐
│ Backend Container       │
│                         │
│ Spring Boot             │
│ Doma                    │
└────────────┬────────────┘
             │
             │ JDBC
             ▼
┌─────────────────────────┐
│ Oracle Container        │
│                         │
│ Oracle Database         │
└────────────┬────────────┘
             │
             ▼
      Docker Volume
```


## 3. Frontend

FrontendはReactで実装する。

ReactアプリケーションをBuildし、
生成された静的ファイルをnginxから配信する。

BrowserからBackend APIへ直接アクセスせず、
`/api/*` へのリクエストをnginxからBackendへ転送する。


## 4. Backend

BackendはSpring Bootで実装する。

Frontendから受信したREST APIリクエストを処理し、
Domaを利用してOracle Databaseへアクセスする。

BackendからOracle Databaseへ接続する際は、
Docker ComposeのService名を利用する。


## 5. Database

DatabaseにはOracle Databaseを使用する。

Oracle DatabaseはDockerコンテナとして実行し、
初回起動時に初期化スクリプトを実行する。

初期化処理では以下を実施する。

- アプリケーション用DBユーザーの作成
- テーブルの作成
- シーケンスの作成
- トリガーの作成
- 初期データの登録

初期化済みの場合は、再初期化を行わない。


## 6. データ永続化

Oracle DatabaseのデータはDocker Volumeに保存する。

コンテナを停止または再作成した場合でも、
Volumeを削除しない限りDatabaseのデータを保持する。


## 7. コンテナ間通信

Docker Composeによって作成されるNetworkを利用して、
各コンテナ間で通信する。

```text
Frontend
    │
    └── backend:8080
             │
             ▼
          Backend
             │
             └── oracle:1521
                      │
                      ▼
                   Oracle
```

コンテナ間通信では、固定IPアドレスではなく
Docker ComposeのService名を利用する。
