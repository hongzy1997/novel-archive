# 01_実装方針

## 概要

本書では、Novel Archive における実装方針について説明する。

システム設計で定義したレイヤー構成およびパッケージ構成をもとに、実装時の基本方針、採用技術、および共通ルールを定義する。

---

# 役割

実装方針では、本システム全体の実装ルールを定義する。

各レイヤーの責務を明確にし、可読性、保守性および拡張性を考慮した実装を行う。

---

# 実装方針

本システムでは、Spring Boot のレイヤードアーキテクチャを採用する。

各レイヤーの責務を分離し、上位レイヤーからのみ下位レイヤーを呼び出す構成とする。

```text
Browser
    │
React
    │ REST API
Spring Boot
    │
Oracle Database
```

---

# 使用する技術

| 技術              | 用途            | 採用理由                                            |
| --------------- | ------------- | ----------------------------------------------- |
| Spring Boot     | Web Framework | 標準的なJava Webアプリケーションを構築するため                     |
| Doma            | ORM           | SQLを明示的に管理できるため                                 |
| Oracle Database | Database      | 業務システムで広く利用されているため                              |
| Lombok          | コード生成         | 定型コードを削減し、可読性を向上させるため                           |
| Gradle          | Build Tool    | ビルドおよび依存関係を管理するため                               |
| React           | フロントエンド画面の実装  | コンポーネント単位で画面を構築でき、<br>状態管理やREST APIとの連携を学習できるため |

---

# 実装ルール

## フロントエンド

- Reactを利用して画面を実装する。
- API通信処理と画面表示処理を分離する。
- 共通化できるUIはコンポーネントとして管理する。
- 入力値チェックを実施する。

## バックエンド

- Controllerに業務ロジックを実装しない。
- Serviceに業務ロジックを集約する。
- Dao以外でSQLを実行しない。
- Request / Responseを利用し、APIと内部実装を分離する。

---

# 設計理由

- レイヤーごとの責務を分離することで、保守性および拡張性を向上させる。
- 共通ルールを定義することで、実装品質を統一する。
- Spring Bootの標準的な開発手法を採用し、企業開発に近い構成とする。
