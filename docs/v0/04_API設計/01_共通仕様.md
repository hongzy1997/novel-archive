# 共通仕様

## 概要

Novel Archive v0 で提供するREST APIの共通仕様を定義する。

各APIは本書の仕様に従って実装する。

---

## ベースURL

```text
/api
```

小説管理APIでは、以下のURLを使用する。

```text
/api/novels
```

---

## 通信方式

|項目|内容|
|---|---|
|Protocol|HTTP|
|API形式|REST|
|Request形式|JSON|
|Response形式|JSON|
|文字コード|UTF-8|

---

## パスパラメータ

小説IDはパスパラメータとして指定する。

```text
/api/novels/{id}
```

|項目|内容|
|---|---|
|パラメータ名|id|
|データ型|数値|
|必須|必須|
|内容|小説ID|

---

## JSON命名規則

JSONの項目名はcamelCaseを使用する。

```json
{
  "novelId": 1,
  "title": "全職高手",
  "author": "蝴蝶藍",
  "readingStatus": 2,
  "rating": 10,
  "memo": "再読予定"
}
```

---

## 日時形式

日時はISO 8601形式で返却する。

```text
yyyy-MM-dd'T'HH:mm:ss
```

例：

```json
{
  "createdAt": "2026-07-23T21:30:00",
  "updatedAt": "2026-07-23T21:30:00"
}
```

---

## HTTPステータス

|HTTP Status|使用条件|
|---|---|
|200 OK|取得、更新、削除が正常終了した場合|
|201 Created|登録が正常終了した場合|
|400 Bad Request|リクエスト内容に入力エラーがある場合|
|404 Not Found|指定されたデータが存在しない場合|
|500 Internal Server Error|システムエラーが発生した場合|

---

## 正常レスポンス

正常終了時は、処理結果をJSON形式で返却する。

### 取得・登録・更新

対象データをレスポンスボディに設定する。

```json
{
  "novelId": 1,
  "title": "全職高手",
  "author": "蝴蝶藍",
  "readingStatus": 2,
  "rating": 10,
  "memo": "再読予定",
  "createdAt": "2026-07-23T21:30:00",
  "updatedAt": "2026-07-23T21:30:00"
}
```

### 削除

削除成功時はレスポンスボディを返却しない。

---

## エラーレスポンス

エラー発生時は、共通形式のJSONを返却する。

```json
{
  "status": 400,
  "errorCode": "VALIDATION_ERROR",
  "message": "入力内容に誤りがあります。",
  "path": "/api/novels",
  "timestamp": "2026-07-23T21:30:00"
}
```

---

## エラーレスポンス項目

|項目|データ型|内容|
|---|---|---|
|status|number|HTTPステータス|
|errorCode|string|エラーコード|
|message|string|エラーメッセージ|
|path|string|リクエストURL|
|timestamp|string|エラー発生日時|

---

## エラーコード

|エラーコード|HTTP Status|内容|
|---|---:|---|
|VALIDATION_ERROR|400|入力チェックエラー|
|INVALID_PARAMETER|400|パラメータ形式エラー|
|NOVEL_NOT_FOUND|404|対象の小説が存在しない|
|INTERNAL_SERVER_ERROR|500|システムエラー|

---

## 入力チェック

登録APIおよび更新APIでは、以下の入力チェックを実施する。

|項目|条件|
|---|---|
|title|必須、200文字以内|
|author|100文字以内|
|readingStatus|必須、0～3|
|rating|1～10、または未設定|
|memo|1000文字以内|

---

## 読書状態

|値|内容|
|---:|---|
|0|未読|
|1|読書中|
|2|読了|
|3|中断|

---

## 評価

評価は1～10の範囲とする。

未評価の場合はnullを許可する。

---

## Requestクラス命名規則

|処理|クラス名|
|---|---|
|小説登録|CreateNovelRequest|
|小説更新|UpdateNovelRequest|

取得および削除ではRequestクラスを作成しない。

---

## Responseクラス命名規則

小説情報の返却には以下のクラスを使用する。

```text
NovelResponse
```

一覧取得APIでは、`NovelResponse`の配列を返却する。

---

## Controller命名規則

小説管理APIのController名は以下とする。

```text
NovelController
```

---

## Service命名規則

小説管理機能のService名は以下とする。

```text
NovelService
```

---

## 例外処理

例外はController内で個別に処理せず、共通例外処理で変換する。

想定する例外は以下のとおり。

|例外|内容|
|---|---|
|MethodArgumentNotValidException|Request Bodyの入力チェックエラー|
|ConstraintViolationException|パスパラメータ等の入力チェックエラー|
|NovelNotFoundException|対象小説が存在しない|
|Exception|想定外のシステムエラー|

---

## 設計方針

- URLはリソース単位で設計する。
- 処理内容はHTTP Methodで表現する。
- リクエストとレスポンスはJSON形式とする。
- EntityをAPIレスポンスとして直接返却しない。
- 入力用Requestクラスと出力用Responseクラスを分離する。
- エラー形式は全APIで統一する。
- 例外処理は共通化する。
