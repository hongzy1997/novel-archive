## 1. 状態管理概要

Frontendでは外部の状態管理ライブラリを使用せず、Reactの`useState`を利用してComponent単位で状態を管理する。

複数画面で共通利用する表示言語のみ`App`で管理し、各画面へpropsとして渡す。

```text
App
└─ 共通状態
   └─ language

各Page
└─ 画面固有状態
   ├─ API取得データ
   ├─ 入力値
   ├─ loading
   └─ error
```

## 2. App

`App`では表示言語を管理する。

| 状態 | 内容 |
|---|---|
| language | 現在の表示言語 |

`language`は`Header`および各Pageへpropsとして渡す。

```text
App
 │
 │ language
 ├──────────────┐
 ↓              ↓
Header         Page
```

## 3. NovelListPage

小説一覧画面では主に以下の状態を管理する。

| 状態 | 内容 |
|---|---|
| novels | Backendから取得した小説一覧 |
| searchText | タイトル検索文字列 |
| loading | 一覧取得中かどうか |
| error | 一覧取得エラー |

### 3.1 一覧データ

画面初期表示時にBackend APIから小説一覧を取得し、`novels`へ保存する。

```text
画面表示
   ↓
API取得開始
   ↓
loading = true
   ↓
GET /api/novels
   ↓
成功
   ├─ novels更新
   └─ loading = false
```

API取得に失敗した場合は`error`を設定する。

### 3.2 検索状態

タイトル検索文字列は`searchText`で管理する。

入力された検索文字列と`novels`を利用して、画面に表示する小説を絞り込む。

検索のためにBackend APIを再実行せず、取得済みの一覧データをFrontend側で絞り込む。

## 4. NovelDetailPage

小説詳細画面では主に以下の状態を管理する。

| 状態 | 内容 |
|---|---|
| novel | Backendから取得した小説情報 |
| loading | 詳細取得中かどうか |
| errorType | 詳細取得時のエラー状態 |
| deleteError | 削除処理時のエラー |

画面表示時にURLから`novelId`を取得し、対象小説をBackendから取得する。

```text
novelId
   ↓
GET /api/novels/{novelId}
   ↓
novel
```

削除処理のエラーは、詳細取得エラーと分けて`deleteError`で管理する。

## 5. NovelCreatePage

小説登録画面では入力値および登録処理の状態を管理する。

主な状態は以下とする。

| 状態 | 内容 |
|---|---|
| title | タイトル |
| author | 作者 |
| readingStatus | 読書状態 |
| rating | 評価 |
| memo | メモ |
| errors | Frontend Validationエラー |
| submitError | 登録処理時のエラー |
| duplicateError | タイトル重複エラー |

入力値はユーザー操作に応じて更新する。

```text
入力操作
   ↓
useState更新
   ↓
NovelFormへpropsとして渡す
```

登録時は現在の入力値からRequestデータを作成し、Backend APIへ送信する。

## 6. NovelEditPage

小説更新画面では、現在の入力値に加えて更新前のデータも保持する。

主な状態は以下とする。

| 状態 | 内容 |
|---|---|
| title | タイトル |
| author | 作者 |
| readingStatus | 読書状態 |
| rating | 評価 |
| memo | メモ |
| initialData | 更新前の小説情報 |
| errors | Frontend Validationエラー |
| loading | 小説情報取得中かどうか |
| error | 初期データ取得エラー |
| submitError | 更新処理時のエラー |
| duplicateError | タイトル重複エラー |

画面初期表示時にBackendから対象小説を取得する。

取得したデータは入力値として設定するとともに、`initialData`として保持する。

```text
GET /api/novels/{novelId}
   ↓
取得データ
   ├─ 現在の入力値へ設定
   └─ initialDataへ保存
```

リセット操作では`initialData`を利用して、入力内容を更新前の状態へ戻す。

## 7. 入力値の管理

登録・更新画面ではPage Componentが入力値を管理し、`NovelForm`へpropsとして渡す。

```text
NovelCreatePage / NovelEditPage
        │
        │ value
        │ onChange
        ↓
     NovelForm
```

`NovelForm`で入力操作が行われると、親Pageから渡された処理を通して状態を更新する。

そのため、入力値の状態は`NovelForm`自身ではなくPage Componentが保持する。

## 8. エラー状態

Frontendでは用途に応じてエラー状態を分けて管理する。

```text
errors
= 入力項目ごとのValidationエラー

submitError
= 登録・更新APIの一般エラー

duplicateError
= タイトル重複エラー

error / errorType
= データ取得時のエラー
```

エラーの種類を分離することで、表示箇所および表示内容を制御する。

## 9. loading状態

Backendからデータを取得する画面では`loading`を管理する。

```text
API開始
 ↓
loading = true
 ↓
API終了
 ↓
loading = false
```

`loading`中は通常の画面内容を表示せず、読込中であることをユーザーへ表示する。

## 10. 状態管理の範囲

状態は必要な範囲でのみ保持する。

```text
全画面で必要
→ App

特定画面だけで必要
→ Page

UI部品だけで完結する一時的な状態
→ Component
```

現在の構成では複雑な画面間共有状態がないため、Redux等の外部状態管理ライブラリは使用しない。
