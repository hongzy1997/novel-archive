## 概要

本書では、本システムにおけるテスト方針について説明する。

品質を確保するため、正常系・異常系・入力チェック・データ整合性の観点からテストを実施する。

---

# テスト目的

本システムが設計どおりに動作することを確認する。

また、不正な入力や異常発生時においても適切な動作となることを確認する。

---

# テスト方針

以下の単位でテストを実施する。

- バックエンド単体テスト
- API動作確認
- フロントエンド動作確認
- フロントエンド・バックエンド連携確認
- データベース確認
- 他のPCからのアクセス確認
- Docker環境での動作確認

---

# テストツール

| ツール            | 用途           |
| -------------- | ------------ |
| JUnit          | バックエンド単体テスト  |
| api-test.http  | API動作確認      |
| Browser        | React画面・連携確認 |
| DBeaver        | DB確認         |
| Docker Desktop | コンテナ環境確認     |

---

# 設計理由

品質を一定水準以上に維持し、安全にリリースするため。
